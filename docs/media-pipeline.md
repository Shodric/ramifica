# Media pipeline

How story media is produced, normalized, and stored. Models and credentials are in [AI configuration](ai-configuration.md); the author side is [Creating stories](creating.md).

## Output profile

`functions/src/config/ai.ts` owns the profile: 480 × 854 vertical video, H.264 with yuv420p, AAC audio, faststart. Generated clips run 10 seconds. Every `ffmpeg`/`ffprobe` invocation passes `-nostdin`, so a hung stdin can never stall a function.

Request values are hints, not enforcement: the pipeline stores what the provider returns (browser-compatible MP4) and records the probed dimensions and duration. Nothing is scaled, cropped, trimmed, or rejected for size. Uploaded clips keep their duration.

## Generation flows

- Images: Meta `/images/generations`, or a local ComfyUI workflow when `AI_IMAGE_PROVIDER=comfy`. Each frame is center-cropped without distortion, then hashed.
- Voice: the narrator line goes to TTS as signed 16-bit little-endian mono PCM (default 24 kHz, see `TTS_PCM_SAMPLE_RATE`), converted to M4A for the app.
- Video: OpenRouter `/videos` with the start frame (first-frame conditioning only), 480p, 9:16, 10 seconds. The extracted last frame of each finished clip is stored for playback and for chaining the next node's start.
- Transcription: complete takes go to Meta `/asr/transcribe`; live dictation streams through the Cloud Run relay instead.

Missing credentials fail every generator explicitly with a reason and clear terminal pending states. Empty keys cannot generate media.

## Creator uploads

A signed-in creator may upload one `mp4` or `mov` under 100 MB to `uploads/{uid}/`. `onUploadFinalized` validates the object and re-encodes it through the same H.264/AAC faststart pipeline, so uploads and generated clips share one playback shape. Clients cannot read the upload back through the SDK; playback uses signed URLs only.

## Stability

Existing assets are never regenerated by migration. A pending provider job keeps its submitted prompt until resumed, and another take keeps the preceding take visible until a validated replacement arrives. Finish pending jobs before switching video backends or models: the new endpoint may be unable to poll the old job IDs.
